# HLS Ahead

一个 Manifest V3 Chrome 扩展：发现当前页面发出的 HLS/m3u8 请求，并提前拉取媒体分片，尝试用浏览器 HTTP 缓存降低后续播放等待。

## 安装

1. 打开 `chrome://extensions/`。
2. 开启右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择本目录。
4. 打开视频页面并开始播放，点击工具栏中的 HLS Ahead 查看状态。

修改代码后，在扩展管理页点击该扩展的刷新按钮。

## 工作方式

- 监听页面成功完成的 m3u8 请求，也能根据响应的 MPEGURL Content-Type 识别不带 `.m3u8` 后缀的地址。
- Master Playlist 默认选择 `BANDWIDTH` 最高的一路，防止同时下载多档清晰度。
- 点播清单预拉取开头若干分片；直播清单预拉取末尾若干分片。
- 同时预拉取 `EXT-X-MAP` 初始化分片和 `EXT-X-KEY` 密钥资源。
- 优先在页面上下文执行请求，以复用该页面的 Cookie、网络缓存分区和鉴权环境；跨域读取失败时使用兼容模式。

## 局限

- HTTP 响应若使用 `Cache-Control: no-store`，预拉取不能形成可复用缓存。
- DRM、Service Worker 自定义缓存、短时签名、一次性 Token 或特殊请求头可能使预拉取失败。
- 浏览器和播放器可能使用各自的缓存策略，因此「已拉取」不等于播放器一定命中缓存。
- 扩展需要 `<all_urls>` 权限才能发现并拉取跨域 CDN 资源。它不会上传捕获到的地址。
- 当前版本不持久保存每个标签页的运行统计；Chrome 回收扩展后台后统计可能归零。

## 调试

在 `chrome://extensions/` 中打开本扩展的 Service Worker 检查器。页面弹窗会显示最近发现的清单、成功拉取数、流量和失败数。
